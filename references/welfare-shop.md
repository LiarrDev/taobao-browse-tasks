# 模块：淘宝福利购（手动触发）

> 入口是 deeplink `https://m.tb.cn/h.jmGPoVQ`。**2026-11-22 已在 LIO-AN00（1176×2400）实测跑通**：4 轮 BROWSE 全部入账（+12 / +11 / +6 / +9 能量），当天 5 个任务全部完成。实测锚点见文末「实测数据」。

只做浏览类任务，判定完全沿用 `task-classification.md`，**不新增白名单**。与「小黑盒集钥匙」一样是常驻的手动模块，默认运行不包含。

## 触发条件

| 情况 | 是否执行 |
|---|---|
| 用户说「做福利购任务」「淘宝福利购」「福利购」「攒能量领红包」 | ✅ 执行本模块 |
| 用户只说「做淘宝任务」「芭芭农场」「淘金币」 | ❌ 走主流程（农场 + 金币） |
| 用户没提福利购，但首页 / 活动页 / 弹窗里出现福利购入口 | ❌ 不执行 |
| 主流程任务列表里出现「浏览福利购会场」类行 | ❌ 不执行本模块；主流程照旧按分类规则把它当普通 BROWSE 处理 |

触发后**只跑这一个模块**；只有同句还提了农场/金币，才在本模块跑完后继续主流程。

## 与主流程的差异

1. **入口是 adb + deeplink**，不走金刚区 / 「我的淘宝」。
2. **进页先处理弹窗，有两种形态**：
   - **形态 A（2026-11-22 实测）**：进页直接自动弹出任务抽屉 `J_WF_Drawer_N`，标题就是「**做任务攒能量领红包**」，没有福利红包弹窗 → 直接在抽屉里做任务（W4）。
   - **形态 B（用户描述）**：「福利红包」弹窗 → 点「**立即收下**」→ 静置约 3 秒 → 「**做任务攒能量领红包**」浮层 → 点「**去浏览**」。该按钮是**就地任务**：点完浮层关闭、不跳转，在当前页**上滑 1 次**（走 `keepalive_swipe.py`）→ **静置 15 秒** → 任务完成。
   - 两种形态都没有 → 直接去任务列表（W3）。
3. **任务列表由「做任务 赢能量」按钮拉起**（形态 A 已在抽屉里就不用再点）。
4. **入账锚点优先「能量」数字**（页面 / 列表顶部的能量值），其次是任务行 `(n/N)` 与「已得 N 能量」提示。能量节点未实测，读不到时以 `(n/N)` 为准。
5. 其余（ref 生命周期、点击后校验落点、列表滚到底、数字锚点、`(n/N)` 做满、循环保护、风控停手）与主流程一致，以 `SKILL.md` 为准。

## W0 前置

与 `SKILL.md` 阶段 -1 / 阶段 0 相同，运行目录带模块名：

```bash
python3 .agents/skills/taobao-browse-tasks/scripts/init_run.py --module welfare --max-tasks 150 --max-minutes 60
```

⚠️ **开跑前先防锁屏**（中途锁屏 `secure=true`，ADB 解不开，只能等人工）：

```bash
adb -s <serial> shell settings put system screen_off_timeout 1800000
```

## W1 打开 deeplink 进活动页

```bash
adb -s <serial> shell am start -a android.intent.action.VIEW -d "https://m.tb.cn/h.jmGPoVQ" com.taobao.taobao
```

`adb` 取绝对路径（`which adb`），`-s` 跟 `mobile_list_available_devices` 返回的 id。

- ⚠️ **不要用 `mobile_open_url`**：https 短链的默认 handler 是系统浏览器，链路会落到浏览器 → 点「打开」→ 淘宝 `wakeup-transit` 中转页，等多久都唤不回淘宝。能用 adb 就用 adb。
- **可能先落错误页**：`text="网页无法打开"` + `net::ERR_...`。这不是活动失效，点中间的「刷新」即可；不要在报错页判失败，也不要反复重发 `am start`。
- 校验：`sleep 3` → `mobile_get_foreground_app` 为 `com.taobao.taobao`，list 读到福利购活动页（顶部活动标题 / 能量数字 / 「做任务 赢能量」按钮，具体文案以实机为准）。
- 白屏 / 元素少 → 再等一轮（3 / 4 / 3.5 秒错开，带递增 echo 标记），最多三轮。活动已下线（提示活动结束、找不到「做任务 赢能量」）→ 汇报即可，不反复重进。

## W2 处理进页弹窗（福利红包 → 做任务攒能量领红包）

进页后等渲染完，每次弹窗变化都重新 list。**没有弹窗就直接进 W3/W4。**

1. **福利红包弹窗**：出现「**立即收下**」→ 点它（ref 优先，落错 BACK 重来）。
   - 只点「立即收下」。其它文案（「去使用 / 去下单 / 开通 / 授权」）一律 X /「关闭」/「取消」。
2. `echo "welfare-popup wait-3"; sleep 3` → 再 list，找「**做任务攒能量领红包**」浮层：
   - 点「**去浏览**」（任务抽屉里的版本可能写作「去完成」）→ 浮层/抽屉关闭，**留在当前页**。
   - 立刻上滑 1 次（拟人化弧线，别用固定直线）：

     ```bash
     python3 .agents/skills/taobao-browse-tasks/scripts/keepalive_swipe.py \
       --device <serial> --run-dir <run_dir> \
       --swipes 1 \
       --x-min 360 --x-max 440 --y-min 1670 --y-max 1750 \
       --dist-min 260 --dist-max 330 --duration-min 520 --duration-max 780
     ```

   - `echo "welfare-popup static-1"; sleep 15`（实操取 16~18 秒留余量），期间不滑不点不识屏。
   - 睡醒校验：`mobile_get_foreground_app` 仍是 `com.taobao.taobao`；跳第三方 → BACK，回不来则 HOME 重发 deeplink（W1）。
   - 判入账：能量数字变大 / 出现「任务完成 / 已得 N 能量」/ 弹层里对应行推进。读不到任何锚点按「已上滑 1 次 + 静置 15 秒」记 `done`，备注「无数字锚点可校验」。
3. **没有「福利红包」弹窗**：直接看有没有「做任务攒能量领红包」弹窗，有就按第 2 步做；都没有就进 W3。
4. **点了「立即收下」后 3 秒弹窗没出现**：等一轮（3 / 3.5 / 4 秒各 list 一次），仍无就进 W3——该弹窗可能当天只弹一次，任务列表里通常还有同名浏览行，别原地死等。
5. **「去浏览」点完实际跳走了新页面**（版本差异）：不要找弹窗了，按 W4 的落地页形态分流做满 15 秒再 BACK，回到活动页后进 W3。
6. 弹窗任务本身只做一次；之后其它浮层（「下单得能量」「开通会员」等）一律 X /「关闭」/「取消」。

## W3 打开任务列表

- 找「**做任务 赢能量**」按钮（文案中间可能带空格，`text=` 与 `label=` 都要匹配）→ 点击。
  - 该按钮在 dump 里**没有文本节点**（实测 2026-11-22），只能按页面坐标点：**中心 ≈ (858,670)**（1176×2400），在「我的能量值」数字正下方。
- 点完 `sleep 2` → list，校验弹出任务抽屉：`J_WF_Drawer_N` + 标题「**做任务攒能量领红包**」+ 右上 X ≈ (1050,897)。
  - 抽屉行结构：首行 `node_N_task_0` 于 y=1224，**行距 ~243px**，按钮列中心 **x≈990**；首行按钮中心 ≈ **(990,1332)**，第二行 ≈ (990,1575)。
  - 2026-11-22 实测只有 **5 行**，滚到底无新行；每次返回后抽屉会关闭，**每轮都要重新点 (858,670) 打开**。
- 找不到按钮 → 在活动页下滑 1~2 屏再 list（用 `keepalive_swipe.py --swipes 1`，慢速长行程）→ 仍无则 `adb exec-out screencap` 截图定位 → 仍无则放弃并汇报，建议移除本模块。
- ⚠️ **不要点错入口**：「赚更多金币」是淘金币、「去赚能量」是双十一赛车，都不属于本模块；本模块只认「做任务 赢能量」。
- 活动页其它按钮（抽奖 / 兑换 / 玩法 / 下单入口）一律不点。

## W4 只挑浏览类

## W5 终止与收尾

满足任一条件即停：滚到底仍无 BROWSE（所有槽位做满或 DONE）、轮数达 `max_tasks`（150，纯兜底）、耗时达 `max_minutes`（60，**实际刹车**）、设备离线 / 闪退 / **活动入口失效**（deeplink 打不开、找不到「做任务 赢能量」、提示已结束 → 汇报「入口可能已下线」）。

收尾：按 HOME 退出，再 `log_task.py --finish` 生成报告并作为交付物呈现。汇报格式沿用 `SKILL.md`（模块列写「淘宝福利购」），小结额外说明弹窗任务是否命中（「立即收下 → 去浏览」做了 / 当天无弹窗）与跳过拆分。

## 已知坑（本模块特有）

- **两层弹窗有先后**：形态 B 下先「立即收下」再「做任务攒能量领红包」，3 秒左右才出第二层；点完第一层立刻找第二层会扑空。形态 A 直接出抽屉，没有这层。
- **「去浏览」不跳转**：形态 B 下它只是关浮层 + 发任务，所以必须自己上滑 1 次并静置 15 秒；点完直接 BACK 会丢掉这次任务。任务抽屉里的同一动作按钮写作「**去完成**」。
- **弹窗每天/每次进入的触发条件可能不同**：没有弹窗不代表模块失效，任务列表才是主战场。
- **抽屉每轮都会关**：做完一个任务返回后抽屉消失，必须重新点「做任务 赢能量」≈ (858,670)，别以为任务列表丢了。
- **「浏览精选商品」页只滑 1 次**：浮标写「下滑浏览15秒」，实测**一次上滑 + 15 秒**即完成，连发滑动反而容易点进商品详情。
- **「去芭芭农场施肥」不是玩法任务**：本模块内它是纯浏览——落地农场页静置 18 秒即完成，**不要点「施肥」**（会消耗肥料，还可能被当成玩法操作）。
- **截图坐标 ≠ 屏幕坐标**：截图缩到 maxSize 以内，坐标点击前务必换算。
- **中途自动锁屏会卡死整场**：开跑前设 `screen_off_timeout 1800000`；已锁屏就请用户解锁。
- **验证弹窗 / 账号失效**：与主流程同处置——滑块拼图人脸停手交人工、冷却 ≥ 30 分钟；落到 `UserLoginActivity` 不输任何凭据，停止本模块。
