## 触发条件

**只能由用户主动触发，任何情况下都不自动跑。**

| 情况 | 是否执行 |
|---|---|
| 用户说「做直播任务」「刷直播任务」「做一下直播体力」「双十一体力任务」「逛直播间任务」 | ✅ |
| 用户只说「做淘宝任务」「芭芭农场」「淘金币」 | ❌ 走主流程 |
| 用户没提直播，但首页有双十一入口 / 正值双十一 | ❌ |
| 主流程列表里出现「逛直播间」 | ❌（主流程看直播类一律跳过） |

触发后只跑本模块；只有同句还提了农场/金币，才在跑完后继续主流程。

## 与主流程的三条差异

1. **入口是 deeplink**，不走金刚区 / 「我的淘宝」。
2. **只做「逛直播间」类**。主规则里「看直播 XX 秒」是 OTHER，**本模块内被白名单覆盖**；反过来，主流程的 BROWSE（会场、逛店）在本模块**不做**。
3. **直播间内不滑动，等 7 秒返回**（铁律 9 的唯一例外）：滑动会切到下一个直播间，还会带出点赞 / 购物车互动。

其余机制（ref 生命周期、点击后校验落点、列表滚到底、数字锚点、`(n/N)` 做满、循环保护）与主流程一致，以 `SKILL.md` 为准。

## L0 前置

与 `SKILL.md` 阶段 -1 / 阶段 0 相同，另外：

```bash
python3 .agents/skills/taobao-browse-tasks/scripts/init_run.py --module live --max-tasks 80 --max-minutes 60
adb -s <serial> shell settings put system screen_off_timeout 1800000   # 防锁屏
```

- 上限 `max_tasks=80` 纯兜底，**真刹车是 `max_minutes=60`**。
- **这个活动不可能自然收尾**：槽位做完立刻换新主播，时间给多少就刷多少。

**节奏与预算**（实测四轮迭代后的最优）：一轮 ≈ **26~30 秒**，60 分钟排 **60~70 轮**。首版文档写的「63 秒/轮」「111 秒/轮」都是决策开销吃掉的（每轮多读一次整屏 dump 或一次图像），**别按挂钟感觉提前收尾**——跑到一半发现只用了十几分钟是正常的。

| 时间上限 | 可做轮数 |
|---|---|
| 20 分钟 | ~40 轮 |
| 60 分钟 | **60~70 轮** |

## L1 打开 deeplink 进活动页

```bash
adb -s <serial> shell am start -a android.intent.action.VIEW -d "https://m.tb.cn/h.jYxQ70Q" com.taobao.taobao
```

- ⚠️ **`mobile_open_url` 走不通**：https 短链默认交给系统浏览器（`com.huawei.browser`），点「打开」只到淘宝的 `wakeup-transit` 中转页，前台仍是浏览器；中转页那个「点击前往」是 WebView 自绘，**uiautomator 树里不存在、拿不到 ref**，别在它上面耗轮次。只在完全不能跑 adb 的环境才退回这条。
- 活动真实名称不是「直播体力」：落地页 `WebView text="直播攒红包"`（也叫「游中国寻宝」），奖励单位是**步数**，标题栏有「累积已得¥X.XX」。
- **首次打开必现错误页**：`text="网页无法打开"` + `net::ERR_THIRD_PARTY_NETWORK_205 [-1]` → 点一次「刷新」（`Button text="刷新" id="com.taobao.taobao:id/uik_errorButtonPos`）即正常。**不要判成活动失效，也不要反复重发 `am start`。**
- 校验：`sleep 3` → 前台 `com.taobao.taobao` + list 读到 `WebView text="直播攒红包"` 与「剩余NNN步数」。白屏再等一轮（3 / 4 / 3.5 错开 + 递增 echo），最多三轮。活动已下线（入口消失 / 提示结束）→ 汇报并建议按移除清单删除本模块。

活动页底部三按钮组 `View id="buttonGroup" at=30,1767 1116x171`，**最右一个**是「赚步数」：

- `TextView text="赚步数" at=975,1875 size=126x51`，容器 `View at=930,1767 216x171`，中心 ≈ **(1038,1852)**。ref 可点，点偏就取容器中心，**点完立刻 list 校验**。

## L3 只挑「逛直播间」

判定输入同样是标题 + 副标题 + 按钮，**默认跳过**。顺序：

1. 先套 `task-classification.md` 的第 1~3 类，命中即跳过（优先于白名单）。特别注意：**预约直播、订阅直播、开播提醒、关注主播属 OTHER**——长得像直播任务也一律跳过。
2. 剩下的行再看是否命中直播间白名单：

| 任务行 | 进度 | 判定 |
|---|---|---|
| 逛一逛精选直播间 | (5/10) | ✅ **首选**：+1000 步/轮 |
| 逛某主播直播间（蜜蜂惊喜社 / 林依轮 / 烈儿宝贝 / 陈洁KiKi…） | (0/3) | ✅ +600 步 |
| 邀请好友集步数 | (0/5) | ⛔ OTHER |
| 去淘金币逛逛 / 去农场1分钱领水果 / 逛一逛芭芭农场 | (0/1) | ⛔ 非直播间（前者）／涉下单（后者） |
| 看短视频领金豆 | (0/1) | ⛔ 短视频 ≠ 直播间 |
| 20点李佳琦预售开启 | (0/1) | ⛔ 预约/预售；且该行实测**被裁切**（容器仅 54 高）不可点 |

- 灰区：标题「去直播间看看有没有想要的」+ 按钮「去看看 / 去逛逛」→ `BROWSE_LIVE`；按钮「去预约 / 去关注 / 去抢」→ 跳过。
- **列表要滚到底**：本列表**不是**会冻结 dump 的 poplayer（每次 list 都刷新），但一屏只显示 9~10 行、最底一行常被裁切成 54 高不可点。滑到底再收尾；`adb shell input swipe 588 2050 588 1100 450` 才推得动（从 y=1700 起滑经常纹丝不动，会误判成到底）。到底硬判据 = 再滑一次后截图与上一张完全一致。
- 日志 `--verdict` 仍写 `BROWSE`（不新增枚举），`--note` 注明「直播间任务」。

## L4 执行一轮逛直播间

**一轮两次调用**（实测 26~30 秒）：一次点击 + 一条 Bash（内含日志、等待、校验、BACK、截图），再一次 Read 读裁图。

1. **点击**：`adb shell input tap x y` 直接点该行「去完成」（**别用 ref**）。x/y 每轮抖动 ±3px——Auto 模式会把参数完全相同的重复点击判成 Duplicate action 拦掉。行坐标可直接复用：第 2 行 ≈ (1014,884)、第 4 行 ≈ (1017,1277)、第 5 行 ≈ (1017,1472)，行距 ≈ 195px，按钮列 x≈954~1080；**某槽位消失后整体上移一格，需重量**（见「已知坑」）。
2. **一条 Bash 干完**：`log_task.py` 补记**上一轮** → `sleep 4` → `dumpsys window | grep mCurrentFocus` 校验 → `sleep 12~14`（停留够）→ `adb shell input keyevent 4` BACK → `sleep 3~4` → `screencap` + PIL 裁图。时长在 12/13/14/15/16 之间错开、echo 带递增标记。
   - zsh 不做变量分词，别写 `AD="$A -s $D"` 再 `$AD shell ...`（会当文件路径报错），定义函数 `ad() { "$A" -s "$D" "$@"; }`。
   - **落地校验只看 focus**：出现 `com.taobao.taobao/com.taobao.taolive.room.TaoLiveVideoActivity` 即进了原生直播间，纯文本零 token。**不是它 = 未入账，重做该轮**（长时间休息后第一发点击可能落到 `WeexV2Activity`）。
3. **读进度只裁 2~5 行**：`crop((150,780,830,1560))`（680×780）足够看清四行的 `(n/N)`。开局仍先 list 一次拿准坐标，收尾核对总账时才再 list。
4. **直播间内什么都不做**：不滑动（滑=切直播间）、不点赞、不点商品卡、不点右侧中部浮标（`id="alv_interactive_2319"`「完成任务/获得奖励」）和「客服点这 / 消费券 / 好运抽奖」。
   - 弹「领取奖励 / 开播提醒 / 登录授权 / 新人福利」浮层 → 找 X 关掉。**不关注、不预约、不授权、不领需要下单的券。**
   - ⚠️ 「主播新人红包 X.XX 元 · 领取后自动关注」这类浮层的 **X 点不动**，但**根本不用关**：它只是盖在直播间上，视频仍在播、计时照走。**原地等满秒数再 BACK 即入账**，绝不点「领」（点了=自动关注）。
   - 部分直播间有声音，不用管，别为静音去点控件。
5. **返回**：BACK 一次即够（实测从不需要连按）。两种落点都算成功：
   - 回**任务列表**（能读到「做任务 集步数」与 `(n/N)`）→ 继续下一轮
   - 回**活动主页**（只有「直播攒红包」+「剩余NNN步数」）→ 再点一次「赚步数」。**别把「没回弹层」当失败去重进。**
   - 最多 5 次 BACK；仍回不到淘宝 → 重启淘宝，从 L1 重进。
   - 偶尔落在直播悬浮窗权限页 `com.taobao.taolive.sdk.permisson.PermissionActivity` → **一律不给权限**，BACK 或点弹层 X ≈ (1110,520) 即回列表，不影响入账。
6. **判定入账（数字锚点优先）**：
   - 任务行 `(n/N)` 的 n 是否 +1（**一批两轮时 n 一次 +2**，等价于两轮都入账）
   - 「**剩余NNN步数**」是否按 +1000 / +600 增加（`text` 字段，dump 冻结也照读）
   - 标题栏「累积已得¥X.XX」可辅助
   - 锚点没动 → 记 `失败-未入账` 并重做（每任务最多 2 次）。读不到锚点（中断后回溯）→ 按「已进直播间 + 停留够 + 返回」记 `完成`，备注说明，**不要因为读不到就判失败**。
7. **领取**（保守）：回列表后按钮变「领取 / 收下」且不含「去使用 / 去下单 / 去玩」→ 点一下即 BACK；没变就不管。
8. **`(n/N)` 做满**：每轮返回重读该行数字，+1 且 < N 原地再来一轮；到 `N/N` / 转「已完成」/ 行消失 → 换下一个；连续 3 次不变 → 记失败加黑名单；单槽位上限 `N + 3`；被上限截断时备注「截断于 x/N」。
9. **记日志**：

   ```bash
   python3 .agents/skills/taobao-browse-tasks/scripts/log_task.py \
     --run-dir <run_dir> --module 直播体力 --name "逛直播间(0/3)" \
     --progress 1/3 --verdict BROWSE --result 完成 --seconds 12 \
     --note "直播间等待7秒；步数 1200→1250，进度推进至(1/3)"
   ```

   跳过的也记（`--verdict OTHER --result 跳过 --note "预约/订阅类，非逛直播间"`）。

## L5 终止与收尾

满足任一即停：滚到底后无 `BROWSE_LIVE`（所有槽位做满或 DONE）、轮数达 `max_tasks`、耗时达 `max_minutes`、活动页失效。

**收尾必做总账自校**（比求和各轮更可靠）：活动主页「赚步数」≈ (1046,1868) → 弹层左上「明细」≈ (90,520) → 「步数明细」逐条列 `时间 + 步数`，关闭 X ≈ (1101,513)。

- 文案能区分来源：自动化浏览落地记「**浏览任务奖励**」，其它来源记「**任务奖励**」。对不上时先看前缀，再对时间戳。
- 例：本次 +9600 而 6 轮 ×1000，差额 3600 = 两次运行之间别人的 6 条 `任务奖励 +600`，6×600 + 6×1000 = 9600 分毫不差。

收尾：按 HOME → `log_task.py --finish`。汇报格式沿用 `SKILL.md`（模块列写「直播体力」），小结额外说明「非直播间类」跳过数、主动触发。

## 已知坑

**槽位无限轮转，且形态三种**（不要按标题重置计数，只看计数器与步数）：

1. **原地换人 / 换名**：`(3/3)` 做满后同一行立刻换成另一个主播的全新 `(0/3)`。
2. **原地冒同名新计数器**：`逛一逛精品直播间 10/10` 后同一行再冒 `(0/10)` → `(0/5)` → `(0/5)`，日志 `--name` 加「（轮转槽位N）」区分。
3. **整行消失、下面上移**：`(0/3)` 主播槽做满后整行移除。**这是完成信号，不是渲染故障。**
4. **N 会递减**：同一行 `(4/10)…(10/10)` → `(0/10)` → `(0/5)`。
5. 轮转池里会混进非直播间任务（「逛一逛芭芭农场」「去快手极速打卡领手机」），**每轮都要重新按 L3 分类**。
6. 偶发**池子真的耗尽**：做满后该行直接变「已完成」灰按钮、不再轮转。收尾判据用两条同时成立：① 再滑一次截图与上一张完全一致；② 到底屏内所有 `逛…直播间` 都是「已完成」。

| 现象 | 处置 |
|---|---|
| **一批里某槽位做满并整行消失，同批后续轮次按旧坐标点到了 OTHER 任务** | 做满会让下方行整体上移一格。把「会做满」那轮排在批次最后，或做满后立刻重读坐标。误点后该任务落地即算完成并照常入账（弹层里仍显示 `(0/1)`，别指望靠它判误点） |
| `(4/5)` 突然变 `(0/5)` | 上一槽位已 `5/5` 并轮转成新槽位（同位置、同奖励文案）。看步数是否入账，**别据此重做** |
| 「未入账」连续两轮读数纹丝不动 | **多半是冷却，不是槽位报废**：切去别的主播槽位 3~5 分钟再回来复测，实测能恢复。判「卡住」前先绕一圈，别急着拉黑 |
| 长时间休息（≥3 分钟）后第一发点击落到 `WeexV2Activity` | 每轮 `mCurrentFocus` 校验不能省；不是 `TaoLiveVideoActivity` 就按未入账重做 |
| 点某行触发 `com.huawei.systemmanager/...AuthLaunchLockedAppActivity` | 系统拦住了它想拉起的第三方 App：**BACK 一次即回淘宝，未离开淘宝、无需黑名单**，绝不输密码 |
| 弹层滑不动 | 用小行程 `y=1700` 起滑会纹丝不动 → 用 `swipe 588 2050 588 1100 450` |
| 两个同名「逛一逛精品直播间」 | 会同时存在两个独立计数器（第 2、3 行各一个 `(x/10)`），`--name` 必须按出现顺序编号，否则报告会把两个计数器混成一条 |
| 活动页自弹「城市知识答题」 | 前进到下一座城市的附带交互，**不在任务列表里，不要答题**，等它消失或点「我知道了」。期间步数会因城市前进被消耗（如 21400→11900），属活动行为，别误判成自己点错 |
| 步数对不上 | 走 L5 的「步数明细」面板核对 |
| 密度超标 | 本模块一轮只要 26~30 秒，很容易冲到 50+ 轮/小时，超铁律 13 的 25 轮/小时。**每 8~10 轮主动停 1~2 分钟**，把 60 分钟当上限而不是目标 |

其他：`mobile_get_foreground_app` 在直播间全屏视频时可能报 `could not determine foreground app`（不是断连，用 list 判当前页即可）；任务中断后手机停在直播间，恢复时先 BACK 一次读锚点。
