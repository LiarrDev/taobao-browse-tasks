## 触发条件（硬约束）

**只能由用户主动触发，任何情况下都不自动跑。**

| 情况 | 是否执行 |
|---|---|
| 用户明确说「做赛车活动」「双十一赛车」「赛车任务」「刷赛车」「做下赛车」「赚能量任务」 | ✅ 执行本模块 |
| 用户只说「做淘宝任务」「刷淘宝任务」「芭芭农场」「淘金币」「赚更多金币」 | ❌ 不执行，走主流程（农场 + 金币） |
| 用户没提赛车，但你看到首页 / 淘金币首页有双十一赛车入口 | ❌ 不执行 |
| 主流程跑淘金币时路过赛车入口 / 任务列表里出现赛车类任务 | ❌ 不执行（主流程照旧按分类规则处理） |

触发后**只跑这一个模块**；只有用户同一句里还提了农场/金币（如「做赛车活动，顺便刷下淘金币」），才在赛车跑完后继续主流程。

⚠️ **本模块与淘金币共用「领淘金币」入口**（都要先落到淘金币首页），**绝不能因为途经淘金币首页就顺手把淘金币任务做了**。淘金币首页上「赚更多金币」是本模块的**干扰项**，不是目标入口。

## 与主流程的三条差异（不要套用通用规则）

1. **入口是「首页 → 领淘金币 → 赚能量」**，不是芭芭农场的「集肥料」，也不是淘金币的「赚更多金币」。第三段按钮换成「**赚能量**」。
2. **只做浏览类任务，判定规则完全沿用 `task-classification.md`，不新增任何白名单**。赛车活动里凡是涉及玩法本身的任务（「去赛车」「去前进」「加油」「挑战」「PK」「开宝箱」「领奖」）**一律跳过**——那些消耗的是能量，不是浏览。
3. **其余机制**（ref 生命周期、点击后校验落点、列表要滚到底、数字锚点判定、多轮 `(n/N)` 做满、循环保护、风控停手）**与主流程完全一致**，未在此重复的部分一律以 `SKILL.md` 为准。

## R3 执行一个浏览任务

**完全沿用 `SKILL.md` 阶段 3 的第 1~9 步**，本模块不另起流程。要点：

1. **点击**：优先该行右侧按钮的 `ref`；ref 不可靠（弹层树过期）时用中心坐标，**点完立刻 list 校验落点**，落错 BACK 重来
2. **落地页分流**（每轮重新判，不要沿用上一轮子类）：
   - 搜索页（有 `EditText` + 「搜索发现 / 历史搜索」）→ 点推荐词进结果页，再保活
   - 静置型（整屏一条内容 / 视频详情 + 顶部倒计时或「浏览 15 秒得 XX」）→ **什么都不做，静置 18 秒再 BACK**
   - 会场 / 店铺 / feeds → 连发滑动保活
3. **拦截二次弹窗**：「新手引导」「授权」「领取」浮层一律 X / 关闭 / 取消，**不接受任何授权**
4. **连发滑动保活**：一次 `scripts/keepalive_swipe.py`（默认随机 8~12 次，单步 1~3 秒停顿）；退出码 42 = 命中滑块 / 人脸验证 → **立即停止本模块所有操作**，交人工，账号冷却（铁律 12）
5. **判定完成只认数字锚点**（本模块优先用这几个）：
   - 任务行 `(n/N)` 的 n 是否 +1
   - 页面上的**能量数字**是否增加（如「能量 1234」→「能量 1284」）
   - 顶部提示条是否变成「**已得 N**」类文案 / 任务行按钮转「已领取」
   - 锚点明确没动 → 记 `失败-未入账` 并**重做这一轮**（每任务最多 2 次重试，计入铁律 5）
6. **返回**：按**一次** BACK → `sleep 2` → list 判断回到了哪一层，**不要连按**。三种落点都算正常，按落点决定下一步：
   - 回到**任务列表**（能读到任务行 `(n/N)`）→ 直接继续下一轮
   - 回到**赛车活动主页** → 再点一次进入任务列表的那个按钮（R1.3）
   - 回到**淘金币首页**（`WebView text="淘金币首页"`）→ 再点一次「赚能量」（R1.2）
   - 回到**首页金刚区** → 按 R1.1 重进
   - 最多 5 次 BACK；仍回不到淘宝 → `mobile_launch_app` 重启淘宝，从 R1.1 重进
7. **领取**（保守）：回列表后按钮变「领取 / 收下」且文案不含「去使用 / 去下单 / 去玩」→ 点一下，点完立刻 BACK；没变就不管
8. **多轮 `(n/N)` 做满**：每轮返回后**重新 list 读该行数字**，+1 且 < N 就原地再来一轮（重新拿 ref）；到 `N/N` 或按钮转「已完成 / 已领取 / 明日再来」或该行消失 → 换下一个；进度连续 3 次不变 → 记失败并加黑名单；单槽位最多 `N + 3` 轮
   - ⚠️ 槽位轮转换名时 `--name` **沿用该槽位第一次出现的标题**（新标题写进 `--note`），否则报告会把同一个槽位拆成好几条「未满」
9. **每轮记一行日志**：

   ```bash
   python3 .workbuddy/skills/taobao-browse-tasks/scripts/log_task.py \
     --run-dir <run_dir> --module 赛车活动 --name "浏览某某会场 15 秒" \
     --progress 1/3 --verdict BROWSE --result 完成 --seconds 34 \
     --note "连发11次滑动；能量 1234→1284(+50)，进度 (0/3)→(1/3)"
   ```

   跳过的同样要记，方便复盘规则是否合理：

   ```bash
   python3 .workbuddy/skills/taobao-browse-tasks/scripts/log_task.py \
     --run-dir <run_dir> --module 赛车活动 --name "驾驶赛车前进 100 米" \
     --verdict OTHER --result 跳过 --note "赛车玩法本身（消耗能量），非浏览类"
   ```

## R4 终止与收尾

满足任一条件即停止：

- 列表滚动到底后仍无任何 `BROWSE`（所有槽位做满或转 DONE）

## 已知坑

### 与淘金币共用入口带来的混淆（本模块最需要注意的一条）

- **「领淘金币」是共用入口**：赛车活动和淘金币主流程都从首页金刚区这个入口进，落到同一个 `WebView text="淘金币首页"`。区别只在下一个按钮：**赛车点「赚能量」，淘金币点「赚更多金币」**。点错了就进了另一个模块的任务列表，白跑一轮。
- **禁止顺手做淘金币任务**：本模块的 `--module` 一律写 `赛车活动`，即使任务行看起来和淘金币那边一模一样。用户没提淘金币就不做。
- **返回时可能落在淘金币首页而不是任务列表**：正常，再点一次「赚能量」即可。别把「没回到任务弹层」当成失败去重进。
- **「赚能量」可能不在首屏**：淘金币首页是长 H5，往下滑 1~2 屏找；list 不到文案就截图看。

### 其余

- **⚠️ 本模块锚点未实测**（2026-10-18 建立）。「赚能量」按钮、任务列表容器、能量文案的真实形态都要等首次运行确认，届时回填本文档。探索阶段多花几轮是正常的，**不要把「没找到」快速判成失败**——先走完 list → 下滑 → 截图三步再放弃。
- **金刚区一律坐标点击**：`label="领淘金币"` 有两层重叠的同 label 节点，ref 点击会点偏（实测点到「天猫汽车」）。
- **截图用 adb 抓**：`adb -s <serial> exec-out screencap -p > <path>`。`mobile_save_screenshot` 写不进 run 目录。
- **截图坐标 ≠ 屏幕坐标**：截图默认缩到 maxSize 1024 以内，用坐标点击前务必换算。
- **能量数字是本模块最好用的锚点**：和淘金币的「金币余额 / 完成进度 x/y」同理，是 `text` 字段，即使弹层 dump 冻结也能读到新值。优先看它，其次看任务行 `(n/N)`。
- **赛车玩法按钮不要碰**：「前进」「加速」「加油」「挑战」「开宝箱」「领奖」都会消耗能量或产生承诺，不在浏览任务范围内。
- **看直播类在本模块照旧跳过**：赛车活动里若出现「看直播得能量」，按主规则 OTHER 跳过（本模块不沿用直播体力模块的白名单例外）。
- **ref 点击仍会点偏**：H5 容器里同 label 节点重叠是常态，点完一律 list 校验落点。
- **风控**：滑动保活期间若弹出滑块 / 人脸验证（`keepalive_swipe.py` 退出码 42）→ 立即停手交人工，账号冷却 ≥ 30 分钟。另外本机脚本的验证拦截**是静默失效的**（`uiautomator dump` 在本机会被 kill，dump 恒空，脚本照样打印 OK），所以每 2~3 轮补一张 `adb exec-out screencap` 截图人工看一眼。
- **循环保护**：Bash `sleep` 不要连发参数完全相同的命令，用不等长序列 + 递增 echo 标记（如 `sleep 3; echo "race-wait-1"` / `sleep 5; echo "race-wait-2"`）。保活本身走 `keepalive_swipe.py` 单进程，不受影响。
