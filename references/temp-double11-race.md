## 触发条件

**只能由用户主动触发，任何情况下都不自动跑。**

| 情况 | 是否执行 |
|---|---|
| 用户说「做赛车活动」「双十一赛车」「赛车任务」「刷赛车」「做下赛车」「赚能量任务」 | ✅ |
| 用户只说「做淘宝任务」「芭芭农场」「淘金币」「赚更多金币」 | ❌ 走主流程 |
| 用户没提赛车，但首页 / 淘金币首页有赛车入口 | ❌ |
| 主流程跑淘金币时路过赛车入口 | ❌ |

触发后只跑本模块；只有同句还提了农场/金币，才在跑完后继续主流程。

⚠️ **与淘金币共用「领淘金币」入口**（都落到 `WebView text="淘金币首页"`），分岔在下一个按钮：**赛车点「赚能量」，淘金币点「赚更多金币」**。点错就进了另一个模块。**途经淘金币首页也不许顺手把金币任务做了。**

## 与主流程的三条差异

1. **入口是「首页 → 领淘金币 → 赚能量」**，不是「集肥料」，也不是「赚更多金币」。
2. **只做浏览类，判定完全沿用 `task-classification.md`，不新增白名单**。赛车活动里凡涉及玩法本身（「去赛车」「前进」「加油」「挑战」「PK」「开宝箱」「领奖」）**一律跳过**——那些消耗能量，不是浏览。
3. 其余机制（ref 生命周期、点击后校验落点、列表滚到底、数字锚点、`(n/N)` 做满、循环保护、风控停手）与主流程一致，以 `SKILL.md` 为准。

## R0 前置

与 `SKILL.md` 阶段 -1 / 阶段 0 相同，另外：

```bash
python3 .agents/skills/taobao-browse-tasks/scripts/init_run.py --module race --max-tasks 80 --max-minutes 60 --device <serial>
```

- 防锁屏已自动化：`init_run.py` 记录原熄屏时间并临时设为 30 分钟，`--finish` 自动恢复；**不要手写 `settings put`**。异常中断时手动跑 `scripts/screen_timeout.py --device <serial> --run-dir <run_dir> --restore`。

耗时：滚动型一轮 ≈ 35~55 秒，静置型 ≈ 30 秒，60 分钟约 70~90 轮。`max_tasks=80` 纯兜底，**真刹车是 `max_minutes`**。

⚠️ **上面是「纯设备时间」，规划时必须按 17~20 轮/小时 算**（2026-10-27 实测：60 分钟完成 17 轮，单轮墙钟 65~80 秒）。差额来自每轮不可省的三次代理往返——点行 → 判 `mCurrentFocus` → 落 `TMSActivity` 时还要补一张截图判形态，加上回弹层后的 `race_probe.py` 对账。**结论：`50/50` 一轮跑不满，约需 3 小时**；开跑前就把预期告诉用户，别按 70~90 轮承诺。

## R3 执行一个浏览任务

完全沿用 `SKILL.md` 阶段 3 的第 1~9 步。要点：

> 🔁 **用 `scripts/browse_round.py` 跑，别再手工分流**（2026-11-05 实测 13 轮全自动、0 失败）：
>
> ```bash
> python3 .agents/skills/taobao-browse-tasks/scripts/browse_round.py \
>   --device <serial> --run-dir <run_dir> --y <已确认是浏览行的按钮中心 y> \
>   --rounds 9,10 --rest 27 --static 20 \
>   --expect-ys 958,1172,1385,1598,1811,2025,2238
> ```
>
> 它自己完成「点击 → `mCurrentFocus` + 白屏率分流 → 静置/连发/搜索页点词+点卡 → 逐次 BACK 回弹层 → 留对账拼图」，搜索中间页不再需要人工停下点词。
> ⚠️ **它不认标题**：点中第三方/玩法行会直接跳走。y 必须先看 `race_probe.py` 拼图确认是浏览行，且**每轮重排后重新定位**；脚本报 `NO_JUMP`/`UNKNOWN` 时回退手工。

1. **点击**：按 `race_probe.py` 给的 y 点按钮列中心（x≈1023）。点完用 `dumpsys window | grep mCurrentFocus` 判落地类型（比截图快）：

   | `mCurrentFocus` | 子类 | 动作 |
   |---|---|---|
   | `...detail2.core.framework.NewDetailActivity` | STATIC | 静置 18~20 秒不滑动 |
   | `com.taobao.search.uniform.SearchActivity` | SEARCH | 点「搜索发现」推荐词进结果页，再按结果页处理 |
   | `...feimagesearch.IrpActivity` | BROWSE（拍立淘） | 双列图片结果页，不弹授权；停留 5~6 秒即可（无横幅可读，靠回弹层 `(n/N)` 判账） |
   | 其他（`TMSActivity` 等） | 会场 / feeds | 连发滑动保活 |

   ⚠️ **`TMSActivity` 本身不区分「会场」和「搜索中间页」**——两者容器同名，但会场要连发滑动、搜索中间页滑动无效必须先点推荐词。**落到 `TMSActivity` 必须补一张截图判形态**（搜索中间页特征：顶部「搜索有福利」+ 大搜索框 + 「历史搜索」/「搜索发现」词块；会场特征：顶部直接是「浏览15秒可领⚡400」横幅 + 双列商品卡）。漏判会把整轮滑在静态搜索页上、白等不入账。
   ⚠️ **白屏率 `wf` 判搜索型不可靠**：拍立淘落地顶部一条横幅区也是纯白（实测 0.64~1.0），会被误判成搜索中间页。**唯一可靠判据仍是 `mCurrentFocus` + 截图形态**。
2. **形态逐轮漂移**：同一槽位这轮落 `NewDetailActivity`（静置）、下轮落 `TMSActivity` 会场（连发滑动），**两类都正常入账，每轮重新判**。
3. **「浏览5秒」类槽位（拍立淘 / 搜一搜）计时不靠滑动**：实测一次轮次里滑动脚本根本没执行，只在结果页停留约 15 秒就返回，`(1/5)→(2/5)` 照样入账。这类用「点词 → 停留 → BACK」即可，连发滑动只是保险，不是必要条件（与主流程 15~30 秒会场不同）。
   - ⚠️ **2026-10-29 反例**：「搜一搜你心仪的宝贝(浏览15秒)」这一轮只在结果页停留 18 秒（能量 pill 未变，39090 原地）→ **判未入账**；同一槽位改成「点词 → 结果页点一张商品卡 → 详情静置 20 秒」后 +400 到账。结论：**停留即入账只适用于「浏览5秒」档与拍立淘；「浏览15秒」档一律按双列 feeds 走「点商品卡 + 详情静置」**，别只停在结果页。
4. **拦截二次弹窗**：新手引导 / 授权 / 领取一律 X /「关闭」/「取消」，不接受任何授权。
5. **连发滑动保活**：`scripts/keepalive_swipe.py`（默认随机 8~12 次拟人化弧线滑动，单步 1~3 秒不规则停顿）。退出码 42 = 命中滑块/人脸 → 立即停手交人工，冷却 ≥ 30 分钟。⚠️ 本机脚本的验证拦截**静默失效**（`uiautomator dump` 被 kill），每 2~3 轮补一张截图人工看一眼。
6. **判定入账（数字锚点）**：
   - 弹层顶部 **「当前进度 n/50」**——dump 冻结时**唯一可靠**的入账锚点，每轮 BACK 后读一次。到 50/50 封顶后不再增长，改用能量数字。
   - 落地页右侧浮标「已得⚡400」/「下单再得⚡2000」（读可以，**别点**）。
   - **能量余额在淘金币首页 / 赛车主页左上「⚡ 剩余 N 能量」**，弹层里读不到——**这是最直观的入账锚点**（不要为了读它去点主页的车库/尾翼/车轮，那些消耗能量）。
   - 锚点没动 → 记 `失败-未入账` 并重做（每任务最多 2 次）。
7. **返回**：BACK 一次 → `sleep 2` → 判落点，**不要连按**。
   - ⚠️ **搜索型的 BACK 次数取决于落地容器，不是固定 3 次**（2026-10-27 一次运行内两种都遇到）：
     - 落 `com.taobao.search.uniform.SearchActivity` → 结果页 → 搜索中间页 → 仍是搜索中间页（只是滚动位置变了）→ 弹层，**要吃 3 次**；前两次 BACK 后 `mCurrentFocus` 仍是 `SearchActivity`，第三次才变回 `TMSActivity`。
     - 落 `com.taobao.themis.container.app.TMSActivity`（「搜索有福利」H5 中间页）→ **1 次 BACK 即回弹层**。
     - 每次 BACK 后先看落点再决定要不要再按（`dumpsys input_method | grep mInputShown` 可快速判键盘是否还开着），别中途以为卡住就乱点。
   - 四种落点都正常：任务弹层（继续）/ 赛车主页（点进任务列表）/ 淘金币首页（再点「赚能量」）/ 首页金刚区（按 R1.1 重进）。
   - 最多 5 次 BACK；仍回不到 → 重启淘宝，从 R1.1 重进。
8. **领取（这里有真奖励）**：顶部黑条「当前进度 n/50」右侧三档（+1000 / +2000 / +4000）。到 50/50 时第三档从灰变红「**立即领取**」→ 点完变「已领取SSR车饰 +4000」并附赠活动道具。这是纯领取按钮，不产生交易，**可以做**。回列表后行内按钮变「领取 / 收下」同理点一下即 BACK。
   - ✅ **2026-10-28 实测成功**：弹层滚到顶时该档是 `Button text="50次任务得车饰，立即领取，奖励4000" at=816,651 303x159` → **中心 (967,730)**，点一次即到账（能量 30760→34760）。旧记录的 (967,674) 偏上，改用 730。
   - ⚠️ **进度封顶后「当前进度 n/50」失效**：到 50/50 后它不再变化，**只能改用「弹层左上能量 pill（⚡35960，中心 ≈ (125,262)）+ 该行 `(n/N)` 加一 / 整行消失」**判账。能量 pill 在弹层打开时就可见，不必关弹层去主页读。
   - ⚠️ **红色「立即领取」≠ 已达门槛**：41/50 时第一档仍显示红「立即领取 +1000」，点 3 次（含 5 秒间隔重试）**能量与档位态毫无变化**。别把它当入账失败去重做任务，按「待人工处理」记一条即可。
   - ⚠️ **该档在弹层内，坐标要按全屏截图换算**（×1.815）：`race_probe.py` 的小图把 head 区原样贴出，直接量小图坐标会点到状态栏（实测 (468,100) 无效，正确 ≈ (644,526)）。
9. **`(n/N)` 做满**：每轮重读该行数字，+1 且 < N 原地再来一轮；到 `N/N` / 转「已完成」/ 行消失 → 换下一个；连续 3 次不变 → 记失败加黑名单；单槽位上限 `N + 3`。**换名但计数器连续 = 同一槽位**，`--name` 沿用首次标题（新标题写进 `--note`）。
10. **记日志**：

```bash
python3 .agents/skills/taobao-browse-tasks/scripts/log_task.py \
  --run-dir <run_dir> --module 赛车活动 --name "浏览某某会场 15 秒" \

```

跳过的也记（`--verdict OTHER --result 跳过 --note "赛车玩法本身（消耗能量），非浏览类"`）。

## R4 终止与收尾

满足任一即停：滚到底仍无 BROWSE、轮数达 `max_tasks`、耗时达 `max_minutes`、**入口失效**（淘金币首页找不到「赚能量」/ 提示活动结束 → 汇报「可能已下线，建议按移除清单删除本模块」）。

**收尾必做能量对账**：`剩余 N 能量` 的增量应等于「浏览轮数 × 400」+ 50/50 领奖 4000。对得上即可放心交付；对不上就把差额与可能原因（起始读数竞态）**如实写进 `report.md`**，不要强行归因或改动日志条数。收尾命令只有 `log_task.py --finish`（无专门的 report 生成脚本），对账段落手工追加。

收尾：按 HOME → `log_task.py --finish`。汇报格式沿用 `SKILL.md`（模块列写「赛车活动」），小结额外说明「赛车玩法类」跳过数、主动触发。

## 已知坑

- **共用入口的混淆**（本模块最容易踩）：见「触发条件」下的 ⚠️。`--module` 一律写 `赛车活动`，即使任务行看起来和淘金币那边一模一样。
- **弹层滚动要用「起点低 + 速度慢」**：从 y≈1000 起滑**实测不滚**；从 y≈1800 起、慢速长行程（800px / ~800ms）才成功（行整体上移 239px）。命令：`keepalive_swipe.py --swipes 1 --y-min 1780 --y-max 1820 --dist-min 780 --dist-max 820 --duration-min 750 --duration-max 900`。
- **缩略截图会把「47/50」裁成「4/50」**：进度读数一律用 `race_probe.py` 的拼图（head 区未缩放、640px 宽，能完整显示「当前进度 n/50」）。
- **做满的槽位是「整行消失」而不是变灰**：小槽位（`5/5`）消失后会从顶部补入新槽位（带自己的 `(0/10)` 计数器）；**大槽位（`10/10`）做满后刷新弹层也不补位，可以直接收尾，不必等**。旧的已完成槽位才会显示灰色「已完成」。
- **「列表还有 BROWSE」是常态**：真正的刹车只能是时间/轮数上限，别等列表清空。
- **续跑入口更简单**：上次按 HOME 退出后 `mobile_launch_app` 常**直接回到「做任务赚能量」弹层**（TMS 窗口 token 不变），不用重走「领淘金币 → 去赚能量」。开跑先截一张图确认落点。
- **弹层行位在单次运行内极稳定**（整轮 15 次进出，第 3 行始终 `(1023,1174)`），可复用；但**跨运行 / 有槽位消失后必须重扫**。
- **X 关闭按钮 ≈ (1095,544)**：关掉回赛车主页，左上「⚡ 剩余 N 能量」可读。弹层重开滚动位置保留。
- **能量 pill 只在弹层打开时可见**；关掉弹层落到赛车主页后那个位置会被别的文案占掉。
- **中途自动锁屏会卡死整场**：`init_run.py` 已自动记录并临时调长熄屏时间、`--finish` 恢复；已锁屏就请用户解锁（`input keyevent 26` / `224` + `wm dismiss-keyguard`）。异常中断时手动跑 `screen_timeout.py --restore`。
- **密度**：5 秒短槽位一轮只要 40~70 秒，很容易冲到 30+ 轮/小时（超铁律 13 的 25 轮/小时）。**每 8~10 轮停 1~2 分钟**，或在报告里显式标注超密度。
- **循环保护**：Bash `sleep` 用不等长序列 + 递增 echo 标记（`sleep 3; echo "race-wait-1"` / `sleep 5; echo "race-wait-2"`）。保活走脚本单进程，不受影响。
- **`report.md` 的「多轮槽位进度」一节不可信**：它按 `--name` 标题聚合，而弹层每轮换名（同一计数器 好物随心逛 → 搜一搜 → 看看#XX 互转），会把一条计数器拆成多行、把 `10/10` 判成「未满」、把中途才出现的行判成「做满」。**交付时以「当前进度 n/50」的位移为准**，并在报告里手写一节说明该口径（2026-10-27 运行：17 轮全部入账 24/50→41/50，聚合表却给出「做满 2 个 / 9 个槽位」）。
- **`race_probe.py` 的 `buttons_y` 是「当前有红色按钮的行」集合，长度/取值会变**：某行变「已完成」后它的 y 会消失、下方补位行的 y 会出现（实测 `[958,1172,1385,1811,2025,2238]` → `[958,1172,1598,1811,2025,2238]`，1385 掉出、1598 补入）。别把「某个 y 不见了」读成弹层挂了。
- **`race_probe.py` 自己会调 `adb`，而本机 adb 不在 PATH** → 直接 `python3 scripts/race_probe.py <png>` 会 `FileNotFoundError: 'adb'`。跑前 `export PATH="$HOME/Library/Android/sdk/platform-tools:$PATH"`（脚本会重新抓一次屏并输出 `<name>_full.png` 拼图，读拼图即可）。
- **弹层滚到底后无法向上回滚**：`keepalive_swipe.py` 只会下滑，`mobile_swipe_on_screen` 的反向直线滑动被铁律 14 禁止；关掉弹层（X）重开后**滚动位置仍保留**（实测确认，不是「可能」）。一旦为了判到底而下滑，本层顶部的大槽位行就再也点不到。**所以：做满一个槽位、需要找下一个 BROWSE 时，先处理当前可见行，把「下滑到底」留到本轮最后一步**；若确实还要做顶部的行，只能重进弹层所在页面（关弹层 → 回淘金币首页 → 再点「去赚能量」）重建列表。
- **弹层会在两次读数之间整块轮转**（2026-10-30 实测）：「拍立淘逛感兴趣的宝贝(3/5)」入账后，同一 y 位置直接换成「头条刷热点领现金(0/1)」（THIRD_PARTY），该行并未做满也没变灰，而是**整行被移出列表**。判「这个槽位还能不能继续做」不能只看上一轮的 y，必须重新看图确认该行还在不在；被移出的多轮槽位按「截断于 x/N」记录，不要为了找回它去翻弹层。
- **到底之后底部会补出第三方/玩法行**：实测滚到底依次为 好物随心逛(10/10 已完成) / 去百度App领现金 / 头条刷热点领现金 / 每拉1人(10/10 已完成) / 开通88VIP / 去玩趣味小游戏(0/3) / 去快手打卡领手机 + 灰字注释，**唯一可做的浏览行在弹层顶部**——配合上一条，滚到底即等于本次收尾。
- **「去省钱卡领红包(0/1) —— 浏览5秒 +600，按钮「去完成」」**：标题与副标题完全像 BROWSE，但落地是省钱卡开卡权益页（诱导付费开卡）→ 按 OTHER 灰区跳过，汇报里点名等用户决定是否放宽。
- **50/50 封顶后领奖按钮的可见变化是 `race_probe.py` 的 `buttons_y` 多出一个 y**：三档变红「立即领取」时数组会插入 ≈689 这一项，领完又消失——不用读文案就能判「有奖励可领」。
- **弹层滚到底后常常只剩跳过类，浏览槽位会「做完即消失、补入第三方行」**（2026-10-28 实测：8 轮做完后底部只剩 头条刷热点领现金 / 去快手打卡领手机 / 逛一逛支付宝金豆夺宝（THIRD_PARTY）、去玩趣味小游戏(0/3)（GAME）、开通88VIP得大额能量（「去开通」= 开卡交易，OTHER）、每拉1人最高2000能量（邀请，OTHER）+ 一行灰色「已完成」）。看到灰字「注：以上奖励均为最高奖励，以实际获得奖励为准」即到底，**这时可以提前收尾，不用等 60 分钟**（本次 16 分钟 / 8 轮）。
- **灰色「已完成」按钮不是 no-op（2026-11-05 实测）**：10/10 的槽位按钮变灰后**点了照样会跳到落地页**（好物随心逛 10/10 → 双列会场 + 「下单再得⚡2000」横幅），只是不再回填能量（44250 原地）。所以别拿灰按钮当「安全试点位」，也别把它读成「这行点不动」。
- **50/50 封顶后第 1/2 档仍可点领（2026-11-05 实测）**：上一轮跑到 50/50 时只领了第三档 +4000，第 1 档 +1000、第 2 档 +2000 一直显示红「立即领取」（带「最高」灰字），被当成干扰项跳过。本次各点一次：能量 33290→34290→36290，**两档都到账**，按钮随即变「已领取」。结论：41/50 时点不动是**门槛未达**，不是按钮失效；**封顶后要主动把三档全点掉**（坐标：第 1 档 (452,715)、第 2 档 (724,715)、第 3 档 (972,715)，同一行 y≈715）。
- **没有 `finish_report.py` 这个脚本**：收尾只有 `log_task.py --finish`，能量对账要**手工追加**到 `report.md`（起始/结束能量、增量、与「轮数×400」的差额）。实测 17 轮 ×400=6800，能量 18990→26090=+7100，差 +300 属起始读数竞态，如实写出不强行归因。
- **`mCurrentFocus` 在跳转瞬间常报 `com.taobao.tao.welcome.Welcome`**（2026-11-04 实测：搜索门、拍立淘落地各遇到多次），这是窗口切换竞态，**不能据此判形态**。正确做法：等 4~5 秒后再取，并且**只用 `grep -m1 mCurrentFocus` 取整行**——直接 `grep -oE 'com\.taobao\.taobao/[^"]+'` 会命中 dumpsys 里更靠前的 `mFocusedApp` 等行，读数永远对不上。
- **不要为了判形态读整屏截图**：`TMSActivity` 落地后裁 `(0,400,1176,1100)` 算全白像素占比即可分流——**搜索中间页 ≥0.86（实测 0.865/0.866/0.903/0.957），会场/结果页 ≤0.36（实测 0.283~0.361）**，两组无交叠。⚠️ 该指标只用于 `TMSActivity` 内部区分「搜索中间页 vs 会场」；`IrpActivity`（拍立淘）顶部横幅也是纯白，仍按 R3.1 的例外处理。
- **原生搜索门（`SearchActivity`）的「搜索发现」是固定网格，不用整屏 list**：块尺寸 536x188，左列 x=38 / 右列 x=602，行 y=375 / 613 / 852 / 1090 / 1328 → **中心取 (306 或 870, 469 / 707 / 946 / 1184 / 1422)**。要读词只需裁 `(38,375)-(1138,1520)` 一小块放大看，比 70 行的 `mobile_list_elements_on_screen` 省得多；命中「XX怎么选 / 怎么解决 / 好评榜」这类问句/榜单文案就换一格，取纯品类名词。
- **5 秒档搜索槽位（「搜一搜你喜欢的宝贝(浏览5秒)」）实测节奏**：点推荐词 → 结果页停留 10 秒 → **3 次 BACK**（前两次 `mCurrentFocus` 仍是同一个 `SearchActivity` token，第三次才回弹层 `be7b967`）→ +300 稳定入账，5 轮全部做满、整行消失。
- **50/50 封顶后第三档领奖点实测 (972,715)**（旧记录 967,674 / 967,730 都偏）：点一次即从红「立即领取 +4000」变灰「已领取SR车饰 +4000」。**能量读数在弹层打开时裁左上 `(0,230)-(420,340)`** 就能拿到「⚡30910」，不必关弹层。
- **做满行消失后，底部补入的多是第三方行**（2026-11-04：「头条刷热点领现金(0/1)」补到 y≈1811），别把它当成「还有浏览任务可做」。
