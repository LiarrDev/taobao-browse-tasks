# 模块：小黑盒集钥匙（手动触发）

> ✅ 锚点已实测：本机 1176×2400 两次跑通（3 轮 / 12 轮 BROWSE 全部入账）。锚点值见文末「实测数据」，任务行判定见 B3。

只做浏览类任务，入口是 deeplink，**所有落地页一律静置 15 秒再 BACK**。

## 触发条件

**只能由用户主动触发，任何情况下都不自动跑。**

| 情况 | 是否执行 |
|---|---|
| 用户说「做小黑盒任务」「小黑盒任务」「小黑盒」「集钥匙」 | ✅ 执行本模块 |
| 用户只说「做淘宝任务」「芭芭农场」「淘金币」 | ❌ 走主流程（农场 + 金币） |
| 用户没提小黑盒，但首页 / 活动页有小黑盒入口 | ❌ 不执行 |
| 主流程列表里出现「集钥匙 / 开黑盒」 | ❌ 不执行（主流程照旧按分类规则处理） |

触发后**只跑这一个模块**；只有同句还提了农场/金币，才在本模块跑完后继续主流程。

## 与主流程的差异

1. **入口是 deeplink**，不走金刚区 / 「我的淘宝」：adb 唤起短链 → 落地页点「做任务集钥匙」拉起任务列表。
2. **判定完全沿用 `task-classification.md`，不新增白名单**。凡「开黑盒 / 开钥匙盒 / 用钥匙兑换 / 抽奖」这类玩法本身、下单、第三方跳转、游戏，一律跳过。
3. **不做连发滑动保活**（铁律 9 的模块级例外）：不论落地是会场 / 店铺 / feeds 还是沉浸看，进页后原地等 15 秒（页面提示更长时等提示秒数 + 3）再 BACK。滑动对入账没加成，只增加误触商品卡 / 跳走的风险。
4. **入账锚点优先「钥匙」数字**（落地页左上「我的钥匙 N」）与任务行 `(n/N)`。

其余（ref 生命周期、点击后校验落点、列表滚到底、数字锚点、`(n/N)` 做满、循环保护、风控停手）与主流程一致，以 `SKILL.md` 为准。

## B0 前置

与 `SKILL.md` 阶段 -1 / 阶段 0 相同，运行目录带模块名：

```bash
python3 .agents/skills/taobao-browse-tasks/scripts/init_run.py --module blackbox --max-tasks 80 --max-minutes 60
```

⚠️ **开跑前先防锁屏**（中途锁屏 `secure=true`，ADB 解不开，只能等人工）：

```bash
adb -s <serial> shell settings put system screen_off_timeout 1800000
```

## B1 打开 deeplink 进活动页

```bash
adb -s <serial> shell am start -a android.intent.action.VIEW -d "https://m.tb.cn/h.jVRERsc" com.taobao.taobao
```

`adb` 取绝对路径（`which adb`），`-s` 跟 `mobile_list_available_devices` 返回的 id。

- ⚠️ **不要用 `mobile_open_url`**：https 短链的默认 handler 是系统浏览器，链路会落到浏览器 → 点「打开」→ 淘宝 `wakeup-transit` 中转页，等多久都唤不回淘宝。能用 adb 就用 adb。
- **首次打开几乎必定落在错误页**：`text="网页无法打开"` + `net::ERR_THIRD_PARTY_NETWORK_205 [-1]`。**这不是活动失效**，点中间的「刷新」即正常；不要在报错页判失败，也不要反复重发 `am start`。
- 校验：`sleep 3` → `mobile_get_foreground_app` 为 `com.taobao.taobao`，`dumpsys window` 为 `TMSActivity`，list 读到 `WebView text="开盒有喜-线上"` 与左上「我的钥匙 N」。
- 白屏 / 元素少 → 再等一轮（3 / 4 / 3.5 错开，带递增 echo 标记），最多三轮。活动已下线（提示活动结束、找不到「做任务集钥匙」）→ 汇报即可，不反复重进。

## B2 打开任务列表

- 「**做任务集钥匙 ›**」在「我的钥匙」右侧同一行，dump 里是**无文本节点** `TextView at=426,480 size=726x141` → **中心 (789,550) 坐标点击**。
- 点完 `sleep 2~3` 弹出任务弹层：标题「**做任务集开盒钥匙**」+ 副标题「**钥匙仅当日有效**」，右上角 X ≈ (1091,926)。
- ⚠️ 落地页其他按钮（开盒、兑换、抽奖、攻略）**一律不点**——那是玩法本身。
- 弹层机制（实测）：
  - **dump 不冻结**（与签到弹层同款，与农场/赛车弹层相反）：滑动后 list 正常刷新，可直接 list + ref/坐标点击。
  - 行容器 `View at=36,y size=1104x222`，**行距 ~234px**；按钮列 `Button text="去完成" at=876,y size=222x96`，**中心 x≈987**。
  - 弹层重开后**滚动位置保留**；行位跨轮稳定，可复用坐标。
  - **做满的槽位整行消失、下方行上移，新任务从顶部补进**——「某行不见了」是完成信号，不是渲染故障。
  - 弹层内读不到「我的钥匙」（那是落地页节点）；弹层内判入账看**行消失 / 补新行**，总账回落地页读钥匙数校验。

## B3 只挑浏览类

与 `SKILL.md` 阶段 2 一致：list → 逐行分类（标子类 普通 / SEARCH / STATIC）→ **滚到底** → 每处理完一个任务重新识屏。

本模块的补充（不覆盖主规则，只加一条）：

| 任务行形态 | 判定 |
|---|---|
| 开黑盒 / 开钥匙盒 / 用 N 把钥匙兑换 / 抽奖 | ⛔ GAME / OTHER（玩法本身，消耗钥匙） |
| 下单得钥匙 / 买 XX 得 N 把钥匙（去下单 / 去购买） | ⛔ OTHER |
| 邀请好友助力 / 分享集钥匙 / 组队 | ⛔ OTHER |
| 浏览 XX 秒 / 逛 XX 店 / 去逛逛 / 去看看（去浏览 / 去完成） | ✅ BROWSE |
| 搜一搜 XX（去完成 / 去搜索） | ✅ BROWSE（SEARCH） |
| 好物沉浸看 / 看严选推荐商品（去完成 / 去查看） | ✅ BROWSE（STATIC，静置不滑） |
| 看直播 XX 秒 | ⛔ OTHER（本模块不做例外） |
| 已领取 / 已完成 / 明日再来 | — DONE |

**默认仍是跳过**：拿不准就跳过。⚠️ **「有新行」≠「有可做任务」**——做满后同一槽位常补进第三方行（如「去高德免费领水果」），每轮都要重新分类。

## B4 执行一个浏览任务

完全沿用 `SKILL.md` 阶段 3 的第 1~9 步。要点：

1. **点击**：优先该行按钮 `ref`；弹层树过期时用中心坐标，**点完立刻校验落点**，落错 BACK 重来。
2. **落地校验（本模块特有）**：`sleep 4` 后**截图看内容**——会场页有整屏 banner / 券，弹层是米黄底任务行，一眼可分。
   - ⚠️ **`mCurrentFocus` 对会场 / 福利类任务无效**：这类落地页与任务弹层**共用 `TMSActivity`**，focus 一字不变，据此判断会误判成「没落地」并连败。`ShopActivity`（店铺）、`WeexV2Activity`（新品资讯）仍可直接用 focus 判。
3. **静置等待（核心动作，覆盖铁律 9）**：一条 Bash 等 15 秒（页面提示更长就等提示秒数 + 3，如 30 秒等 33 秒），期间**不滑动、不点击、不识屏**：

   ```bash
   echo "bb-static-1 逛雅诗兰黛官方旗舰店"; sleep 15
   ```

   多轮之间 echo 递增、时长在 15/16/17 错开（避开宿主循环保护）。**不要为了「保活」去滑**——本模块实测不需要。搜索型例外：先在搜索页点推荐词进结果页，落页后再静置。

4. **拦截二次弹窗**：新手引导 / 授权 / 领取浮层一律 X /「关闭」/「取消」，**不接受任何授权**。
   - 静置页可能满是诱导（双 11 会场页「¥25 券 + 领 + 开通88VIP」）→ 一个都不点，等满就 BACK，照样入账。
   - 弹「华为应用锁」（`com.huawei.systemmanager/...AuthLaunchLockedAppActivity`）= 系统拦住了第三方跳转：**一次 BACK 即回弹层，不输密码**，按 THIRD_PARTY 拉黑本次不再点。**但拉黑 ≠ 失败**——实测被拦那次迟到入账了，收尾要回看该行状态。这类页面 screencap 是空白/非法 PNG（安全窗口），别浪费轮次读图。

5. **判定入账只认数字锚点**：任务行 `(n/N)` 的 n 是否 +1；「我的钥匙 N」是否增加；提示条是否变「已得 N」/ 按钮转「已领取」。弹层内可看行消失 / 补新行。
   - 锚点没动 → 记 `失败-未入账` 并重做（每任务最多 2 次，计入铁律 5）。读不到任何锚点 → 按「已落地 + 静置等满 + 返回」记 `done`，备注「无数字锚点可校验」。
   - ⚠️ **「未入账」先当冷却处理**：切去做别的槽位 3~5 分钟后回来复测，别急着拉黑。

6. **返回**：按**一次** BACK → `sleep 2` → 校验落点，**不要连按**。三种落点都正常：
   - 回**任务列表**（能读到 `(n/N)`）→ 继续下一轮
   - 回**活动主页**（没有任务行）→ 再点一次「做任务集钥匙」
   - 回**首页**（BACK 可能直接退到 `TBMainActivity`）→ 重发 deeplink（B1）
   - 最多 5 次 BACK；仍回不到淘宝 → `mobile_launch_app` 重启，从 B1 重进。

7. **领取**（保守）：按钮变「领取 / 收下」且文案不含「去使用 / 去下单 / 去玩」→ 点一下即 BACK；没变就不管。
8. **`(n/N)` 做满**：每轮返回重读该行数字，+1 且 < N 原地再来一轮；到 `N/N` / 转「已完成」/ 行消失 → 换下一个；连续 3 次不变 → 记失败加黑名单；单槽位上限 `N + 3`。换名但进度延续视为同一槽位，`--name` 沿用首次标题（新标题写进 `--note`）。
9. **每轮记一行日志**（`--module 小黑盒`）：

   ```bash
   python3 .agents/skills/taobao-browse-tasks/scripts/log_task.py \
     --run-dir <run_dir> --module 小黑盒 --name "浏览某某会场 15 秒" \
     --progress 1/3 --verdict BROWSE --result 完成 --seconds 34 \
     --note "静置15秒未滑动；钥匙 12→13，进度 (0/3)→(1/3)"
   ```

   跳过的也要记（`--verdict GAME --result 跳过 --note "玩法本身（消耗钥匙）"`），方便复盘白名单。

## B5 终止与收尾

满足任一条件即停：滚到底仍无 BROWSE（所有槽位做满或 DONE）、轮数达 `max_tasks`（80，纯兜底）、耗时达 `max_minutes`（60，**实际刹车**）、设备离线 / 闪退 / **活动入口失效**（deeplink 打不开、找不到「做任务集钥匙」、提示已结束 → 汇报「入口可能已下线」）。

收尾：按 HOME 退出，再 `log_task.py --finish` 生成报告并作为交付物呈现。汇报格式沿用 `SKILL.md`（模块列写「小黑盒」），小结额外说明跳过拆分（玩法 / 下单 / 第三方 / 游戏各多少）与「用户主动触发」。

## 已知坑（本模块特有）

- **钥匙仅当日有效**（弹层副标题明示）：当天做到多少算多少，跨天不累计。
- **ref 点击会点偏是常态**：H5 里同 label 节点重叠常见，点完一律校验落点。
- **截图用 adb 抓**：`adb -s <serial> exec-out screencap -p > <path>`。`mobile_save_screenshot` 受 MCP 白名单目录限制，写不进 run 目录。
- **截图坐标 ≠ 屏幕坐标**：截图缩到 maxSize 以内，坐标点击前务必换算。
- **中途自动锁屏会卡死整场**：开跑前设 `screen_off_timeout 1800000`；已锁屏就请用户解锁。
- **验证弹窗**：本模块不滑动，触发率低；万一静置期间弹出，立即停手交人工，冷却 ≥ 30 分钟，绝不重试绕过。
- **循环保护**：Bash `sleep` 用不等长序列 + 递增 echo 标记。
- **活动有时限**：倒计时结束或入口消失即失效，不要反复重进，汇报即可。
