# 模块：小黑盒集钥匙（手动触发）

> ✅ **锚点已实测**（2026-10-25 建立，同日本机 LIO-AN00 / 1176×2400 首次跑通：3 轮 BROWSE / 0 失败，钥匙 15→18 分毫不差）。实测值、弹层机制与任务行判定见文末「首次运行实测记录」。

---

## 触发条件（硬约束）

**只能由用户主动触发，任何情况下都不自动跑。**

| 情况 | 是否执行 |
|---|---|
| 用户明确说「做小黑盒任务」「小黑盒任务」「小黑盒」「集钥匙」 | ✅ 执行本模块 |
| 用户只说「做淘宝任务」「刷淘宝任务」「芭芭农场」「淘金币」 | ❌ 不执行，走主流程（农场 + 金币） |
| 用户没提小黑盒，但你看到首页 / 活动页有小黑盒或集钥匙入口 | ❌ 不执行 |
| 主流程任务列表里出现「集钥匙 / 开黑盒」类任务 | ❌ 不执行（主流程照旧按分类规则处理） |

触发后**只跑这一个模块**；只有用户同一句里还提了农场/金币（如「做小黑盒任务，顺便刷下淘金币」），才在小黑盒跑完后继续主流程。

## 与主流程的差异（不要套用通用规则）

1. **入口是 deeplink**，不走首页金刚区 / 「我的淘宝」：adb 唤起 `https://m.tb.cn/h.jVRERsc` → 落地页点「**做任务集钥匙**」拉起任务列表。
2. **只做浏览类任务，判定规则完全沿用 `task-classification.md`，不新增任何白名单**（用户 2026-10-25 明确要求：只做浏览类，**不下单、不跳转第三方应用、不跳转游戏**）。凡是「开黑盒 / 开钥匙盒 / 用钥匙兑换 / 抽奖」这类玩法本身、下单类、第三方跳转类、游戏类一律跳过。
3. **所有浏览任务落地后一律静置等待，不做连发滑动保活**（用户 2026-10-25 实测要求，铁律 9 的模块级例外）：不论落地是会场 / 店铺 / feeds 还是沉浸看，进页后**原地等 15 秒**（页面提示的浏览时长更长时，等提示秒数 + 3 秒）再 BACK。滑动对入账没有加成，反而增加误触商品卡 / 跳走的风险。
4. **入账锚点优先用「钥匙」数字**（落地页左上「我的钥匙 N」）与任务行 `(n/N)`。

未在此重复的部分（ref 生命周期、点击后校验落点、列表要滚到底、数字锚点判定、多轮 `(n/N)` 做满、循环保护、风控停手）**与主流程完全一致**，一律以 `SKILL.md` 为准。

## B1 打开 deeplink 进活动页（复用直播模块实测经验）

活动链接：`https://m.tb.cn/h.jVRERsc`（实测落地「天猫小黑盒 / 开盒有喜」活动页，见下方校验小节）。

### 主路径：adb 强制淘宝接管（一步到位）

```bash
adb -s <serial> shell am start -a android.intent.action.VIEW -d "https://m.tb.cn/h.jVRERsc" com.taobao.taobao
```

`adb` 取本机绝对路径（`which adb`，macOS 常见 `~/Library/Android/sdk/platform-tools/adb`），`-s` 后跟 `mobile_list_available_devices` 返回的 id。

⚠️ **不要用 `mobile_open_url`**：https 短链的默认 handler 是系统浏览器而不是淘宝，实测链路是落到浏览器 → 点「打开」→ 淘宝唤醒中转页（`wakeup-transit`），等多久都唤不回淘宝（完整踩坑记录见 `temp-double11-live.md` L1）。能用 adb 就用 adb。

### 首次打开必现的报错：点一次「刷新」就好

淘宝被唤起后**第一次几乎必定落在错误页**：

- 页面 `text="网页无法打开"`，副标题 `网络错误,请稍后再试`，底部 `net::ERR_THIRD_PARTY_NETWORK_205 [-1]`
- **这不是活动失效，也不是网络坏了** —— 直接点中间的「刷新」按钮，页面立刻正常加载
- 不要在报错页就把本轮判失败、也不要反复重发 am start

### 校验落地（✅ 已实测 2026-10-25）

`sleep 3` → `mobile_get_foreground_app` 应为 `com.taobao.taobao`，`dumpsys window` 应为 `TMSActivity`。落地页锚点：

- `WebView text="开盒有喜-线上"`（活动名「天猫小黑盒 / 开盒有喜」，页面满是「恭喜XX抽中天猫小黑盒红包」滚动条与商品 feed）
- 落地页左上「**我的钥匙 N**」：`TextView text="N" at≈54,501 size=69x60`（1176×2400）——**钥匙数字锚点①**
- 白屏 / 元素少就再等一轮（时长错开 `3 / 4 / 3.5` 并带递增 echo 标记），最多三轮。活动已下线（提示活动结束、找不到「做任务集钥匙」入口）→ 汇报即可，不要反复重进

⚠️ 本次 adb 直达**未出现** `net::ERR_THIRD_PARTY_NETWORK_205` 报错页（与直播模块不同）；若哪天出现，仍按「点一次刷新即好」处理，别判活动失效。

- 「**做任务集钥匙 ›**」在落地页「我的钥匙」右侧同一行，dump 里是**无文本节点** `TextView at=426,480 size=726x141` → **中心 (789, 550) 坐标点击**（1176×2400）；ref 点击未验证，坐标已稳定复用 3 次
- 点完 `sleep 2~3` 弹出任务弹层：标题「**做任务集开盒钥匙**」+ 副标题「**钥匙仅当日有效**」，右上角关闭 X 中心 ≈ **(1091, 926)**
- ⚠️ 落地页上其他按钮（开盒、兑换、抽奖、攻略等玩法入口）**一律不点**
- 弹层机制（实测）：
  - **dump 不冻结**（与红包签到弹层同款，与芭芭农场/赛车弹层相反）：滑动后 list 正常刷新，可直接 list + 坐标/ref 点击

  - 弹层重开后**滚动位置保留**；首行按钮中心实测 y≈1156/1392/1626（随行数变化），行位稳定可跨轮复用
  - **做满的槽位整行消失、下方行上移，新任务从顶部补进**（与赛车模块一致）——「某行不见了」就是完成信号，不是渲染故障
  - 弹层内读不到「我的钥匙」数字（那是落地页的节点）；弹层内判入账看**行消失 / 补新行**，总账回落地页读钥匙数字校验

## B3 解析任务列表：只挑浏览类

与 `SKILL.md` 阶段 2 完全一致，摘要：

1. list（`format: "text"`），识别「标题 + 副标题（奖励）+ 右侧按钮」的行结构
2. 逐行按 `references/task-classification.md` 分类，并**标上子类**：普通 / `SEARCH`（搜索型）/ `STATIC`（静置型：标题含「沉浸看」或「看严选推荐商品」这类整屏内容流 / 视频型详情）
3. **列表必须滚动到底才算遍历完**（一屏只显示部分行，下方还有）
4. 每处理完一个任务列表常重排，**必须重新识屏定位**

### 本模块的判定补充（不覆盖主规则，只加一条）

小黑盒活动里会出现一批**长得像任务、实际是玩法或交易**的行，全部跳过：

| 任务行形态 | 判定 |
|---|---|
| 开黑盒 / 开钥匙盒 / 用 N 把钥匙兑换 / 抽奖 | ⛔ GAME / OTHER（玩法本身，消耗钥匙） |
| 下单得钥匙 / 买 XX 得 N 把钥匙（按钮「去下单 / 去购买」） | ⛔ OTHER（下单类，铁律 3） |
| 邀请好友助力 / 分享集钥匙 / 组队 | ⛔ OTHER（社交裂变） |
| 浏览 XX 秒 / 逛 XX 店 / 去逛逛 / 去看看（按钮「去浏览 / 去完成」） | ✅ BROWSE，执行 |
| 搜一搜 XX（按钮「去完成 / 去搜索」） | ✅ BROWSE（SEARCH 子类） |
| 好物沉浸看 / 看严选推荐商品（按钮「去完成 / 去查看」） | ✅ BROWSE（STATIC 子类，静置不滑） |
| 看直播 XX 秒 | ⛔ OTHER（主规则：直播页诱导下单，**本模块不做例外**） |
| 已领取 / 已完成 / 明日再来 | — DONE，忽略 |

**默认结论仍是跳过**：拿不准就跳过，宁可漏做，不可乱点。

## B4 执行一个浏览任务

**完全沿用 `SKILL.md` 阶段 3 的第 1~9 步**，本模块不另起流程。要点：

1. **点击**：优先该行右侧按钮的 `ref`；ref 不可靠（弹层树过期）时用中心坐标，**点完立刻校验落点**，落错 BACK 重来
2. **落地校验与静置等待（本模块核心动作，覆盖铁律 9）**：点完 `sleep 3` 用 `dumpsys window | grep mCurrentFocus` 或截图确认已落地（常见 `ShopActivity` = 店铺页、TMS/WebView = 会场），然后**一条 Bash 静置等 15 秒**（页面提示的浏览时长更长时等提示秒数 + 3 秒，如提示 30 秒等 33 秒），期间**不滑动、不点击、不识屏**：

   ```bash
   echo "bb-static-1 逛雅诗兰黛官方旗舰店"; sleep 15
   ```

   - 多轮之间 echo 标记递增、时长在 15/16/17 之间错开，避免连发完全相同命令触发宿主循环保护
   - **不要为了「保活」去滑它**——本模块实测不需要滑动保活，滑动只会增加误触页面底部商品卡 / 「立即购买」跳走的风险
   - 搜索型例外：搜索页要先点「搜索发现」推荐词进结果页，落到结果页后再按本步静置
3. **拦截二次弹窗**：「新手引导」「授权」「领取」浮层一律 X / 关闭 / 取消，**不接受任何授权**
4. **判定完成只认数字锚点**（实测形态：落地页左上「我的钥匙 N」+ 任务行 `(n/N)`，弹层内看行消失 / 补新行）：
   - 任务行 `(n/N)` 的 n 是否 +1
   - 页面上的**钥匙数字**是否增加（「钥匙 NNN」/「已得 N 把钥匙」/「我的钥匙」）
   - 顶部提示条是否变成「**已得 N**」类文案 / 任务行按钮转「已领取」
   - 锚点明确没动 → 记 `失败-未入账` 并**重做这一轮**（每任务最多 2 次重试，计入铁律 5）
   - 读不到任何数字锚点 → 按「已落地 + 静置等满 + 返回」记 `done`，备注「无数字锚点可校验」；多轮任务不走这个兜底
5. **返回**：按**一次** BACK → `sleep 2` → 校验落点，**不要连按**。落在哪一层都算正常，按落点重进：
   - 回到**任务列表**（能读到任务行 `(n/N)`）→ 直接继续下一轮
   - 回到**活动主页**（没有任务行）→ 再点一次「做任务集钥匙」
   - 回到**首页** → 重发 deeplink（B1）重进
   - 最多 5 次 BACK；仍回不到淘宝 → `mobile_launch_app` 重启淘宝，从 B1 重进
6. **领取**（保守）：回列表后按钮变「领取 / 收下」且文案不含「去使用 / 去下单 / 去玩」→ 点一下，点完立刻 BACK；没变就不管
7. **多轮 `(n/N)` 做满**：每轮返回后**重新读该行数字**，+1 且 < N 就原地再来一轮（重新拿 ref）；到 `N/N` 或按钮转「已完成 / 已领取 / 明日再来」或该行消失 / 换文案 → 换下一个；进度连续 3 次不变 → 记失败并加黑名单；单槽位最多 `N + 3` 轮
   - ⚠️ 槽位轮转换名时 `--name` **沿用该槽位第一次出现的标题**（新标题写进 `--note`），否则报告会把同一个槽位拆成好几条「未满」
   - ⚠️ 「未入账」先当冷却处理：切去做别的槽位 3~5 分钟后回来复测，别急着拉黑（直播模块实测过 `(4/10)` 冻结 5 分钟后自愈）
8. **每轮记一行日志**（`--module 小黑盒`）：

   ```bash
   python3 .agents/skills/taobao-browse-tasks/scripts/log_task.py \
     --run-dir <run_dir> --module 小黑盒 --name "浏览某某会场 15 秒" \
     --progress 1/3 --verdict BROWSE --result 完成 --seconds 34 \
     --note "静置15秒未滑动；钥匙 12→13，进度 (0/3)→(1/3)"
   ```

   跳过的同样要记，方便复盘规则是否合理：

   ```bash
   python3 .agents/skills/taobao-browse-tasks/scripts/log_task.py \
     --run-dir <run_dir> --module 小黑盒 --name "开黑盒抽好礼" \
     --verdict GAME --result 跳过 --note "玩法本身（消耗钥匙），非浏览类"
   ```

## B5 终止与收尾

满足任一条件即停止：

- 列表滚动到底后仍无任何 `BROWSE`（所有槽位做满或转 DONE）
- 完成任务数达 `max_tasks`（默认 80，纯兜底）
- 用时达 `max_minutes`（默认 **60**，实际的主要刹车）
- 设备离线 / 淘宝反复闪退 / **活动入口失效**（deeplink 打不开、落地页找不到「做任务集钥匙」、提示活动已结束 → 汇报「活动入口可能已下线或失效」）

收尾：按 HOME 退出，生成报告并作为交付物呈现：

```bash
python3 .agents/skills/taobao-browse-tasks/scripts/log_task.py --run-dir <run_dir> --finish
```

汇报格式沿用 `SKILL.md` 的「汇报格式」（模块列写「小黑盒」），小结里额外说明：完成 N 轮、跳过 M 个（其中玩法/下单/第三方/游戏各多少）、失败 K 个、总耗时、目录；触发方式注明「用户主动触发」。

## 已知坑

### deeplink 这一段（复用直播模块实测经验）

- **`mobile_open_url` 打开 m.tb.cn 短链会落到系统浏览器**（默认 handler 不是淘宝），唤不回淘宝 → **必须用 adb** `am start -a android.intent.action.VIEW -d "<链接>" com.taobao.taobao`
- **若报 `net::ERR_THIRD_PARTY_NETWORK_205`**（「网页无法打开 / 网络错误」），点一次「刷新」即正常，别判活动失效（2026-10-25 实测 adb 直达未出现该报错，但保留此处理）
- 落在浏览器网页版 = 没唤起，不要硬在网页版里点

### 其余

- **钥匙仅当日有效**（弹层副标题明示）：当天做到多少算多少，跨天不累计。
- **「我的钥匙」数字只在落地页可读**，弹层开着时读不到；单轮入账看「整行消失 / 补新行」，隔几轮回落地页读一次钥匙数做总账校验。
- **ref 点击会点偏是常态**：H5 容器里同 label 节点重叠常见，点完一律校验落点。
- **截图用 adb 抓**：`adb -s <serial> exec-out screencap -p > <path>`。`mobile_save_screenshot` 受 MCP 白名单目录限制写不进 run 目录。
- **截图坐标 ≠ 屏幕坐标**：截图默认缩到 maxSize 1024 以内，用坐标点击前务必换算。
- **中途自动锁屏会卡死整场**（锁屏 `secure=true`，ADB 解不开）：开跑前 `settings put system screen_off_timeout 1800000`；已锁屏就停下来请用户解锁。
- **本模块不做滑动保活**（用户 2026-10-25 要求），触发滑块 / 人脸验证的概率很低；万一静置等待期间弹出验证弹窗 → 立即停手交人工，账号冷却 ≥ 30 分钟，绝不重试绕过。
- **循环保护**：Bash `sleep` 用不等长序列 + 递增 echo 标记（如 `echo "bb-static-1"; sleep 15` / `echo "bb-static-2"; sleep 16`）。
- **落地页与任务列表里的玩法按钮**（开盒、兑换、抽奖、攻略等）**全部不点**——那是活动本身，不是任务。
- **活动有时限**：倒计时结束或入口消失即失效，不要反复重进，汇报即可。

### 执行与返回（实测）

- 店铺任务落地 `com.alibaba.triver.triver_shop.newShop.ShopActivity`（部分店铺顶部带直播流，不管它）；**静置 15~17 秒 → `input keyevent 4` BACK 一次 → 直接回弹层**（TMSActivity），滚动位置保留，行位稳定可复用。
- 做满 `(0/1)` 的槽位**整行消失**，新任务（如逛蓝月亮→逛九牧）从顶部补进——每轮 BACK 后靠「目标行还在不在」判入账，别依赖行号记忆。
- 单轮耗时：点击 3s 落地确认 + 静置 15~17s + BACK 2s ≈ **20~22s/轮**（不含识屏开销）；20 分钟上限足够做 30+ 轮，本模块按铁律 13 控制节奏即可。
