# 任务分类判定规则

先读这份文件再动手处理任何任务列表。**默认结论是跳过**：只有当信号明确落在 `BROWSE` 时才执行。

判定输入：任务行的**标题** + **副标题/奖励文案** + **右侧按钮文案**（三者都要看，按钮文案权重最高）。

## 判定顺序

按 1 → 5 依次匹配，**命中即停**。

### 1. THIRD_PARTY（跳过）

标题或按钮指向淘宝之外的 App / 需要离开淘宝：

- 关键词：蚂蚁庄园、蚂蚁森林、支付宝、头条、今日头条、百度、UC、夸克、抖音、快手、京东、拼多多、唯品会、微信、QQ、淘宝特价版、淘特、闲鱼、飞猪、饿了么、菜鸟、网商银行

按钮文案信号：「打开 XX」「去 XX 看看」「下载」「跳转」「前往 XX」

额外处理：把命中的关键词加入本次运行的黑名单，后续遇到同类不再尝试。

### 2. GAME（跳过）

- 关键词：玩、去玩、玩一玩、游戏、挑战、抽奖、转盘、抽卡、刮奖、合成、消除、骰子、投掷、猜、答题、PK、对战、组队、养、喂养、喂食、除虫、治病、羊了个羊、斗地主、麻将、赛车、跳一跳、消消乐、叠叠乐、占卜、测一测
- 也包括芭芭农场内的「去捉虫」「除虫」「杀虫」等互动玩法

### 3. OTHER（跳过）

不是浏览、也不是游戏，但会产生行为承诺或消费：

- 下单支付类：下单、下单返、付款、购买、0 元购、试用、买一送一、先试后买
- 交易意向类：加购、加入购物车、收藏商品、收藏店铺、关注店铺、订阅直播、预约直播、预约开播、开播提醒
- 社交 / 裂变类：邀请好友、邀请新用户、分享给好友、拉人、助力、开红包团
- 合约权益类：开通会员、开通88VIP、签约、开通免密、领取银行卡权益、绑定、实名认证、授权
- 内容互动类：发布、评价、写评价、晒单、上传、投票、举报、答题问卷
- 观看直播类：「看直播 XX 秒」——虽然像浏览，但直播页大量诱导下单，**跳过**（用户要求只做浏览类）

### 4. BROWSE（执行）

信号：按钮或标题明确是「看一眼/逛一圈就给奖励」，且**没有任何上述跳转或消费信号**。

- 按钮文案：去浏览、去逛逛、去逛、去看看、去逛店、浏览、逛 XX 秒、看看
- 标题中含时长：浏览 15 秒、逛 20 秒、看 XX 秒、停留 XX 秒、XXs
- 副标题数字型：+100 肥料、+50 金币、+5 元宝，且动作是「浏览 / 逛」

> ⚠️ 上面的「XX 秒」是**需要持续滑动的时长**，不是「在页面停住等待 XX 秒」。浏览计时器只在页面滚动时累计，停手 2~3 秒就暂停。执行方式见 `mobile-mcp-playbook.md` 的「滑动保活：必须连发」与 `SKILL.md` 阶段 3 第 4 步。

**附加校验**（全部满足才算 BROWSE）：

1. 不含第 1~3 类的任何关键词
2. 按钮文案是「去浏览 / 去逛 / 去看看」这类单向动作，而不是「去下单 / 去玩 / 去关注」
3. 标题未出现具体 App 名（出现就是 THIRD_PARTY）

**灰区处理**：标题是「逛某某会场」「去某某旗舰店看看」这种中性表述，且按钮为「去浏览」→ 判 BROWSE 并执行；若按钮为「去逛店」但同时带「下单返」→ 判 OTHER，跳过。

#### 搜索型是 BROWSE 的子类

标题形如「搜一搜你喜欢的商品」「搜索 XX 得奖励」「搜索有福利」，按钮是「去完成 / 去搜索」→ **判 BROWSE（子类 SEARCH）并执行**。它不是 OTHER：搜索本身不产生交易或关注承诺。

它与普通 BROWSE 的差别只在落地页：点完会先落到淘宝搜索页，**必须点「搜索发现」/「历史搜索」里的推荐词进到结果页**，才是真正的浏览目标页。执行细节见 `SKILL.md` 阶段 3 的「搜索型浏览任务」。

#### 多轮进度任务要做满（`(n/N)`）

标题里的 `(0/8)`、`(1/5)` 这类**不是**「做一次就行」，而是「同一槽位重复做 N 次才算完成」。判定与执行规则：

- `(n/N)` 中 `n < N` → 该槽位**还有可做轮次**，判 BROWSE 并执行
- 执行一轮后回到列表，**重新读该行的进度数字**：`n+1` 且仍 `< N` → 原地再来一轮（重新 list 拿新 ref，不要复用旧 ref）
- 进度到 `N/N`、按钮转「已完成 / 已领取 / 明日再来」、或该行被替换成别的任务 → 槽位做满，换下一个
- **进度没动就不算做过**：回到列表读 `(n/N)`，`n` 没有 +1（且余额、「完成进度 x/y」这类数字锚点也没变）→ 本轮记 `失败-未入账` 并重做这一轮。**绝不要把未入账的一轮计入 N 次**，否则会出现「报告说做满了，淘宝还在给 (2/5)」
- **防死循环**：进度数字连续 3 次不变 → 记「失败」并入黑名单；单槽位最多尝试 `N + 3` 轮
- 被 `max_minutes` / `max_tasks` 截断时，在备注写明「截断于 x/N」

注意淘宝的槽位会**轮转**：做满一个 `(0/8)` 后，同一行可能换成另一个名字继续 `(0/8)`（例如「搜一搜」→「好物沉浸看」）。这是**新槽位**，照常做满；判断依据是进度数字归零 + 标题文案变化，而不是行位置。

### 5. DONE / LOCKED（忽略，不计数）

- 按钮文案：已领取、已完成、明日再来、00:00 后刷新、置灰不可点
- 行整体灰度显示且不可点击

## 计数与记账规则

- 只有真正执行并完成浏览时长的才算「完成」
- 「跳过」要写清判定类别 + 命中关键词，便于用户复盘规则是否合理
- 同一任务执行失败 2 次 → 记「失败」并加入黑名单，不再尝试
