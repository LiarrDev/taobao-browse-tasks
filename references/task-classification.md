# 任务分类判定

**默认结论是跳过。** 只有信号明确落在 `BROWSE` 时才执行——宁可漏做，不可乱点。

判定输入：**标题** + **副标题（奖励文案）** + **右侧按钮文案**，三者都要看，**按钮文案权重最高**。顺序 1 → 5 匹配，**命中即停**。

## 1 THIRD_PARTY（跳过）

指向淘宝之外的 App，或需要离开淘宝。

- 关键词：蚂蚁庄园、蚂蚁森林、支付宝、头条、今日头条、百度、UC、夸克、抖音、快手、京东、拼多多、唯品会、微信、QQ、淘宝特价版、淘特、闲鱼、飞猪、饿了么、菜鸟、网商银行
- 按钮信号：「打开 XX」「去 XX 看看」「下载」「跳转」「前往 XX」
- 命中后把该关键词加入本次运行黑名单，后续同类不再尝试。

## 2 GAME（跳过）

- 关键词：玩、去玩、玩一玩、游戏、挑战、抽奖、转盘、抽卡、刮奖、合成、消除、骰子、投掷、猜、答题、PK、对战、组队、养、喂养、喂食、除虫、治病、羊了个羊、斗地主、麻将、赛车、跳一跳、消消乐、叠叠乐、占卜、测一测
- 含芭芭农场内的「去捉虫 / 除虫 / 杀虫」等互动玩法。

## 3 OTHER（跳过）

不是浏览、也不是游戏，但会产生行为承诺或消费：

- **下单支付**：下单、下单返、付款、购买、0 元购、试用、买一送一、先试后买
- **交易意向**：加购、加入购物车、收藏商品、收藏店铺、关注店铺、订阅直播、预约直播、预约开播、开播提醒
- **社交裂变**：邀请好友、邀请新用户、分享给好友、拉人、助力、开红包团
- **合约权益**：开通会员、开通 88VIP、签约、开通免密、领取银行卡权益、绑定、实名认证、授权
- **内容互动**：发布、评价、写评价、晒单、上传、投票、举报、答题问卷
- **看直播**：「看直播 XX 秒」像浏览，但直播页大量诱导下单 → 跳过（用户只要求浏览类）
- **阅读 / 听书**：「浏览看书赚钱」「听书 / 有声小说 / 书城 / 看小说 XX 秒」。标题带「浏览」、按钮是「去完成」，看着完全像 BROWSE，落地却是听书页 → 命中即跳过。典型：「浏览看书赚钱(0/1) —— 点击有声小说听15秒最高得 +30」

## 4 BROWSE（执行）

信号：按钮或标题明确是「看一眼 / 逛一圈就给奖励」，且**没有任何第 1~3 类信号**。

- 按钮：「去浏览」「去逛逛」「去逛」「去看看」「去逛店」「浏览」「看看」
- 标题含时长：浏览 15 秒、逛 20 秒、看 XX 秒、停留 XX 秒、XXs
- 副标题数字型：+100 肥料、+50 金币、+5 元宝，且动作是「浏览 / 逛」

**附加校验**（全部满足才算 BROWSE）：

1. 不含第 1~3 类任何关键词
2. 按钮是单向动作（「去浏览 / 去逛 / 去看看 / 去完成 / 去搜索 / 去查看」），不是「去下单 / 去玩 / 去关注」
3. 标题未出现具体 App 名（出现即 THIRD_PARTY）

**灰区处理**：

- 「逛某某会场」「去某某旗舰店看看」+ 按钮「去浏览」→ BROWSE 执行。
- 按钮「去逛店」但同时带「下单返」→ OTHER 跳过。
- **「先浏览拿 X，下单再得 Y」= OTHER**：形如「浏览淘宝秒杀 0/1 —— 先浏览拿300,下单赚加倍肥料」。标题以「浏览」开头、按钮是「去完成」，最容易被骗过，但副标题含「下单」→ 第 3 类命中即停（附加校验 1 要求不含任何第 1~3 类关键词）。记账备注「灰区」，汇报里单独点名，由用户决定是否放宽。

### 子类 SEARCH（搜索型）

「搜一搜你喜欢的商品」「搜索 XX 得奖励」+ 按钮「去完成 / 去搜索」→ **BROWSE 执行**。搜索本身不产生交易或关注承诺，不是 OTHER。

与普通 BROWSE 的差别只在落地：点完先落淘宝搜索页，**必须点「搜索发现」/「历史搜索」的推荐词进结果页**才算浏览目标页。执行见 `SKILL.md` 阶段 3「搜索型浏览任务」。

### 子类 STATIC（静置型）

两类成员，**执行方式完全相同**：

| 类型 | 标题形如 | 落地页形态 |
|---|---|---|
| 沉浸看 | 好物沉浸看、沉浸看 XX 秒、沉浸逛 | 整屏图文 / 视频内容流，一屏一条 |
| 视频型详情 | 看严选推荐商品 | 整屏商品视频详情（五棱镜浮标 + 商品卡），不可连续下滚 |

- 按钮「去完成 / 去查看」→ **BROWSE 执行**，不是 OTHER：纯看内容，不产生交易或关注承诺。
- **执行方式与普通 BROWSE 相反**：落页后什么都不做，静置等满提示秒数（通常 15 秒，实操等 18 秒留余量）再 BACK。**不滑动**——计时不靠滚动，滑了不加分，还容易碰到页面底部 / 浮层的商品卡与「立即购买」。
- 落地确认：一屏一条图文或视频卡、dump 里几乎只有图片与视频容器、顶部有倒计时或「浏览 15 秒得 XX」。
- **「看严选推荐商品」落在商品详情页 ≠ OTHER**：它只是借详情页做视频浏览，弹「当前页下单得肥料 / 得金币」浮层点 X /「关闭」即可，**不点「领券购买 / 加入购物车」**就没有交易承诺。曾误判跳过，不要重犯。
- 仍要 `(n/N)` 做满、仍只认数字锚点判入账；日志写「静置 N 秒未滑动」。
- 若点进去其实是普通会场 / feeds（多列商品卡、能连续下滚）→ 不是 STATIC，照旧连发滑动保活。
- ⚠️ **子类按轮次重判，不要沿用**：同一槽位可能第 2 轮改名、第 3 轮落地直接变双列 feeds。**行标题只用于识别槽位，执行方式只由落地页形态决定。**

### 多轮进度槽位要做满（`(n/N)`）

标题里的 `(0/8)`、`(1/5)` **不是**「做一次就行」，而是「同一槽位重复 N 次」。

- `n < N` → 还有可做轮次，执行。
- 执行一轮后回列表**重读进度**：`n+1` 且仍 `< N` → 原地再来一轮（**重新 list 拿新 ref，不复用旧 ref**）。
- 进度到 `N/N`、按钮转「已完成 / 已领取 / 明日再来」、或该行消失 / 换成别的任务 → 槽位做满，换下一个。
- **进度没动就不算做过**：`n` 没 +1（且余额、「完成进度 x/y」也没变）→ 记 `失败-未入账` 并重做这一轮，**绝不把未入账的一轮计入 N 次**，否则会出现「报告说做满了，淘宝还显示 (2/5)」。
- **防死循环**：进度连续 3 次不变 → 记失败并入黑名单；单槽位最多 `N + 3` 轮。
- 被 `max_minutes` / `max_tasks` 截断时，备注写「截断于 x/N」。
- **槽位会轮转**：做满一个 `(0/8)` 后同一行可能换成另一个名字继续 `(0/8)`（如「搜一搜」→「好物沉浸看」→「看严选推荐商品」，**执行方式也跟着变**）。这是新槽位，照常做满；判据是**进度归零 + 标题文案变化**，不是行位置。
- **换名但进度延续 = 同一槽位**：记账 `--name` 沿用首次出现的标题（新标题写进 `--note`），否则报告会把一个槽位拆成多条「未满」。

## 5 DONE / LOCKED（忽略，不计数）

- 按钮：已领取、已完成、明日再来、00:00 后刷新、置灰不可点
- 行整体灰度且不可点击

## 记账规则

- 只有**实际执行、完成浏览时长、且数字锚点推进**的才算「完成」。
- 「跳过」要写清判定类别 + 命中关键词，便于复盘规则是否合理。
- 同一任务失败 2 次 → 记失败并入黑名单，不再尝试。
